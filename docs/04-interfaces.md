## General rules

Scoped tools require `agent_id`; `project_id`, `channel`, `source_instance_id` default to empty strings. Reuse the exact four-string scope on every call. Caller-provided scope is a selector, **not authentication**: one trusted local operator owns the process. Health, resolve and audit are operator-wide and have no scope arguments.

`memory_ref` is opaque `mem:<positive integer>` or `ep:<positive integer>` (max 128); preserve the prefix. CPersona supplies no instance identifier: callers explicitly choose and repeat `source_instance_id`; the configured value is not automatically injected by the MCP wrapper.

Tools do not accept arbitrary source paths or URLs. Normal listing/search returns metadata, not image bytes. Register is an explicit bounded source read and managed copy; get is the explicit image response path. Tool schemas are generated by the MCP SDK from server signatures; domain errors use fixed sanitized codes/messages. SDK schema errors may precede domain result creation.

## Registered tools and inputs

“Scope” below means required `agent_id` plus the three optional strings above.

| Tool | Inputs beyond scope | Result |
| --- | --- | --- |
| bridge_health | no scope; `{}` | bridge/schema version, provider/storage health, managed readiness, warning codes |
| link_asset | `memory_ref`, positive integer `provider_file_id` | `ok`, stable `asset_id`, `link_status`, `media_kind`, optional error |
| unlink_asset | `memory_ref`, `asset_id` | `ok`, `unlinked`, `remaining_links` in exact scope; never deletes files |
| search_assets | `query`, `limit=10` (clamped 1..20), optional `folder_id` | `ok`, `query`, `results`, `search_coverage=exact/partial`, `provider_warning`, error |
| list_memory_assets | `memory_ref`, `limit=20` (clamped 1..100) | `ok`, `memory_ref`, `assets`, error; newest link first, no continuation token |
| get_asset | `asset_id`, optional `memory_ref` | one MCP image content block on success (no structured content); GetAssetResult with sanitized error on failure |
| register_asset | `memory_ref`, positive integer `provider_file_id` | `ok`, stable `asset_id`, actual `link_status`, `deduplicated`, `media_type`, error |
| resolve_pending_assets | no scope; `{}` | `ok`, `premise_ready`, `checked`, `bound`, `waiting`, error; bounded explicit pass |
| audit_assets | no scope; `apply=false` | AuditReport; read-only by default, `apply=true` applies allowed status transitions, never rebinds/deletes |

No `kind`, note, upload, MIME or path argument is registered. Search is image-only, scans up to five provider pages of 20, intersects with exact-scope associations before response, and reports partial when capped. `exact` describes exhausted provider candidate coverage, not a measured semantic recall guarantee. Search entries include IDs, kind/type/size, stored name/status, score and scoped memory refs; list entries are repository metadata.

Link verifies current file kind before creating/reusing an association. Reuse does not replace trusted locator evidence. Current MCP external-link creation does not capture generation, so the indexed-edit waiver is unavailable for those locators. Get checks scope, optional memory membership and fresh identity before fetching; [docs/11 §5](11-id-schema-scope.md) is the complete gate table (D-21/D-22). Unknown/stale identity never authorizes a different file; incompatible is terminal.

Register requires both managed root and folder configuration. It reads an indexed source through the provider, validates bytes, atomically copies under a content-addressed relative path and creates a pending locator. Digest reuse preserves the existing locator/state and adds only the scoped link. It does not accept unindexed local files. Resolve verifies registered/watched folder, raw-page completeness and matching managed identity in listing/detail (D-23/D-24/D-25). Full recent pages remain pending; no automatic background scheduler exists.

## Existing local-search HTTP integration
| Purpose | Current endpoint | Plan |
| --- | --- | --- |
| Find image candidates by text | POST /api/search with q and tab=image | Use for search_assets and attach selection. `page_size` accepts only 20/50/100 (verified in B-01); limit≤20 maps to page_size=20 |
| Find file details | GET /api/files/{file_id} | Validate kind, status, identity/provenance |
| Fetch original | GET /api/files/{file_id}/content | Explicit get_asset only; streamed + bounded |
| Image query | POST /api/search/media | M3 search quality evaluation; not M1 MCP requirement |
| Check health | GET /api/status | Surface availability and index incompatibility |
| List watched folders | GET /api/folders | Read-only premise; operator separately registers the managed folder |
| Pending inventory | GET /api/files/recent?limit=N | raw completeness retained before folder filtering; server cap 100, no pagination |

The HTTP adapter must accept only configured loopback base URL (http://127.0.0.1:18765 by default). Use a trusted HTTP client with strict redirect prevention, bounded response reads, connect/read timeouts, retry only safe idempotent reads, and parse/version-check returned schemas. A provider 409 index_mismatch is an error, not an empty search.

B-01 guard note (docs/10-contract-audit.md): the provider's Host/Origin guard accepts requests that carry **neither** `Origin` nor `Sec-Fetch-Site` (non-browser clients) but requires `Host` to equal `127.0.0.1:<port>`/`localhost:<port>` and refuses repeated headers. The Bridge client must keep that shape: literal IPv4 loopback base URL, no browser-like headers, no redirects.

## Error taxonomy
| Code | Situation |
| --- | --- |
| invalid_request | Invalid IDs/fields/sizes |
| unauthorized_scope | Scope cannot be used under configured trusted-local policy |
| asset_not_found | Unknown asset or asset outside scope (no information leak) |
| asset_unavailable | File missing/offline/stale identity |
| unsupported_media | Returned bytes or source kind unsupported for image tool |
| media_too_large | File or derived payload exceeds bound |
| dependency_unavailable | local-search cannot be contacted |
| index_incompatible | Provider model/index mismatch or API contract conflict |
| storage_error | SQLite transaction or media store failed |
| storage_full | Managed copy could not be stored |
| path_conflict | Managed content path conflict |
| source_unreadable | Explicit import source could not be read |

## Extension points and policy
- A future CPersona-native integration may consume stable asset refs; it must preserve existing text-only recall default and be done in the user's fork under a separate approved PR.
- A future provider could replace local-search behind a typed AssetSearchProvider protocol. No generalized provider framework is necessary for M1.
- No arbitrary file upload/write HTTP endpoint should be introduced to local-search simply to save Bridge media; Bridge manages its opt-in folder and local-search only indexes it.
