# eval — B-14 cross-retrieval benchmark

Explicit CLI; never part of the MCP server, never CI-mandatory against a
live provider. Reuse conventions where compatible with `local-search eval`
(docs/07); metric differences recorded here:

- **qrels by construction** (generated fixtures + declared links). Scores
  prove plumbing correctness end-to-end; they are NOT a semantic-quality
  measurement — the report prints that limitation unconditionally.
- `text_to_image` runs through `bridge.search_assets` (the product surface:
  scoped LINKED assets only). `memory_to_image` through
  `list_memory_assets` (qrels keyed by asset id — docs/04 exposes no
  provider file id there). `image_to_image` via the provider's attachment
  route (`POST /api/search/media`), audited in docs/10 — the Bridge adds
  no image encoder of its own.
- empty/zero-grade qrels ⇒ case **excluded** (`missing_qrels`), never
  scored 0. A task with no scored case reports `unmeasured` with `—`
  cells — never a copied number (docs/07 §output).
- latency excludes warmup priming queries (count stated in env.warmup).
- embedder fingerprint reads `fake` when the server runs the deterministic
  fake embedder (`/api/status` model.revision == "fake").

## Run (against a provider you started yourself)

```sh
uv run python -m eval.run \
  --manifest eval/manifest.example.json \
  --provider http://127.0.0.1:18765 \
  --watched-dir <DIR registered as folder id below, watch on> \
  --managed-folder-id <folder id> \
  --data-dir <throwaway bridge dir> \
  --out reports/eval-$(date +%Y%m%d) [--keep]
```

Writes `result.json` (schema: `eval/schema.json`, versioned) and
`report.md`. Fixture media are generated by the CLI itself (synthetic
PNG/zip only — no personal files, no open-license download step needed)
into `--watched-dir`, discovered through the inventory route once the real
watcher indexes them, and swept unless `--keep` is given. The CLI never
registers folders and never touches provider data outside that folder.

## Solid-color real-model probe

`manifest.colors.json` declares three deterministic solid RGB PNGs and twelve cases: six Japanese/English text queries, three exact-image queries and three memory associations. Grade 3 is assigned only to the stated color's image before execution. This is a tiny controlled color-retrieval probe, not a representative dataset or a model-comparison claim. Run with the same CLI against an isolated provider with real weights; record `/api/status` model revision/device/dtype, provider commit, manifest SHA-256 and the generated per-query report. Never promote the fake-embedder run to real-model evidence.


IMG-06 adds a user-facing `search_assets_by_image` MCP tool that delegates to
the same local-search media endpoint. This evaluation remains separate: fake
embeddings and this tool's availability do not establish retrieval quality.


## Real EmbeddingGemma 2 provenance gate (Issue #76)

When a benchmark is presented as **real-model evidence**, add the strict model
revision gate to the normal command:

\`\`\`sh
uv run python -m eval.run \
  --manifest eval/manifest.colors.json \
  --provider http://127.0.0.1:<DEDICATED-TEST-PORT> \
  --watched-dir <DEDICATED-REGISTERED-IMAGE-DIR> \
  --managed-folder-id <EXACT-TEST-FOLDER-ID> \
  --data-dir <NEW-THROWAWAY-BRIDGE-DIR> \
  --out <PRIVATE-RESULT-DIR> \
  --warmup 2 \
  --expect-model-revision 914f7f89142e33e77833254d9c9b90c3cef7303b
\`\`\`

Placeholders must be replaced with dedicated paths/IDs; the existing
local-search operator must register the folder and start a **real** provider
first. The flag fails before fixture creation if \`/api/status\` reports a fake,
missing, abbreviated or different EmbeddingGemma 2 model. The output records
the provider's reported \`model_revision\` (not proof of artifact bytes;
the model snapshot and other hashes must still be verified separately).

A case whose query fails, or whose labeled relevant fixture was never indexed,
is **not scored as a miss**. Per-query errors and \`partial\` status remain
visible; a task with no valid successful samples is \`unmeasured\`. Do not
cite a partial task's numeric mean as a complete benchmark. The prior
12-query solid-color result is still only a smoke test: realistic images,
graded qrels and image-to-image negatives require additional dataset/evaluator
work in #76; pure Bridge memory-link results do not measure CPersona semantic
recall. For end-to-end CPersona/Bridge/local-search real-model verification,
see #77.
