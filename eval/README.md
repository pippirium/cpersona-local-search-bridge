# eval — B-14 cross-retrieval benchmark

Explicit CLI; never part of the MCP server, never CI-mandatory against a
live provider. Reuse conventions where compatible with `local-search eval`
(docs/07); metric differences recorded here:

- **qrels by construction** (generated fixtures + declared links). Scores
  prove plumbing correctness end-to-end; they are NOT a semantic-quality
  measurement — the report prints that limitation unconditionally.
- `text_to_image` runs through `bridge.search_assets` (the product surface:
  scoped LINKED assets only). `memory_to_image` through
  `list_memory_assets` (qrels keyed by asset id — docs/04 exposes no
  provider file id there). `image_to_image` via the provider's attachment
  route (`POST /api/search/media`), audited in docs/10 — the Bridge adds
  no image encoder of its own.
- empty/zero-grade qrels ⇒ case **excluded** (`missing_qrels`), never
  scored 0. A task with no scored case reports `unmeasured` with `—`
  cells — never a copied number (docs/07 §output).
- latency excludes warmup priming queries (count stated in env.warmup).
- embedder fingerprint reads `fake` when the server runs the deterministic
  fake embedder (`/api/status` model.revision == "fake").

## Run (against a provider you started yourself)

```sh
uv run python -m eval.run \
  --manifest eval/manifest.example.json \
  --provider http://127.0.0.1:18765 \
  --watched-dir <DIR registered as folder id below, watch on> \
  --managed-folder-id <folder id> \
  --data-dir <throwaway bridge dir> \
  --out reports/eval-$(date +%Y%m%d) [--keep]
```

Writes `result.json` (schema: `eval/schema.json`, versioned) and
`report.md`. Fixture media are generated by the CLI itself (synthetic
PNG/zip only — no personal files, no open-license download step needed)
into `--watched-dir`, discovered through the inventory route once the real
watcher indexes them, and swept unless `--keep` is given. The CLI never
registers folders and never touches provider data outside that folder.
